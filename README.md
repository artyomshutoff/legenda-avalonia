# Легенда

Настольное приложение для фитнес-клуба на C#, .NET 8 и Avalonia UI. Данные хранятся локально в SQLite.

## Скачать

Откройте раздел **Releases** и скачайте `Legenda-v2.2.0-win-x64.zip`. Распакуйте архив в папку, доступную для записи, и запустите `Legenda.App.exe`. Установка .NET не требуется.

Публичный архив не содержит базу клиентов или учётные записи. При первом запуске приложение создаст `legenda.db` рядом с EXE. Если на компьютере есть база предыдущей версии в `%LOCALAPPDATA%\LegendaV2\legenda.db` или `%LOCALAPPDATA%\Legenda\legenda.db`, приложение скопирует её при первом запуске. Существующая база рядом с EXE не перезаписывается автоматически. Для переноса данных закройте приложение и скопируйте папку с EXE и `legenda.db`.

Нажмите «Создать первого администратора», задайте свой логин и пароль, затем войдите. Пароли хранятся в виде PBKDF2-хешей с индивидуальной солью. Логин: 3–64 латинских символа, цифры, точка, подчёркивание, @ или дефис. Пароль: 10–128 символов, минимум одна буква и цифра.

## Возможности

- Проверка QR-кода с камеры или ручного ввода номера абонемента. Отдельные звуковые сигналы для успешного прохода, отказа и неизвестного кода. При успешном проходе приложение предупреждает, если до окончания абонемента осталось меньше семи дней.
- Журнал посещений с точной датой и временем; повторное сканирование в течение минуты не создаёт дубль.
- Список клиентов с поиском по имени, телефону и абонементу, копированием данных и экспортом в Excel.
- Создание восьмизначного уникального номера абонемента, просмотр и скачивание QR-кода клиента.
- Продление абонемента с выбранной даты, история операций и внесённых сумм, предупреждение об окончании срока.
- Заморозка абонемента, чёрный список, восстановление удалённых клиентов из корзины.
- Роли администратора и оператора, смена пароля, журнал изменений, резервное копирование и восстановление SQLite-базы.
- Адаптивный интерфейс, выбор камеры и настраиваемый возврат к сканеру после проверки.

## Общая база и работа без интернета

В **Журналы и настройки → Настройки** подключите один и тот же Яндекс Диск на всех компьютерах. Переключатель **Автоматическая синхронизация** включён по умолчанию. Проверка выполняется при запуске и каждые 30 секунд. Есть кнопка **Синхронизировать сейчас** и статус в панели администратора.

При отсутствии интернета данные продолжают сохраняться в локальную `legenda.db`. После восстановления связи или следующего запуска приложение отправляет накопленные изменения и сверяет версии. Общими являются клиенты, посещения, абонементы, история и учётные записи сотрудников. Токен Диска, настройки сканера и другие параметры компьютера остаются локальными и не входят в передаваемые снимки.

Применяется **более новая база целиком**, по времени изменения её данных в UTC; независимые изменения строк на разных компьютерах не объединяются. Версии имеют уникальные имена и не перезаписывают друг друга при одновременной отправке. Если обе базы изменились офлайн, обе версии сначала сохраняются на Диске, затем выбирается более новая. Перед заменой локальной базы создаётся копия в `sync-safety` рядом с EXE. Если пользователь редактирует форму или изменил данные во время скачивания, автоматическая замена откладывается. Повреждённые копии не применяются.

На Диске используется папка **Легенда / Общая база** с 10 последними версиями SQLite; локально сохраняются 10 страховочных копий. Это отдельная история от резервных копий при выходе. Для доступа к прежним данным можно восстановить нужный `.db` через настройки. Восстановление пользователем считается новым изменением и будет синхронизировано.

На новом компьютере создайте временную учётную запись администратора, чтобы настроить подключение. Если общая база уже существует, начальная база нового приложения загружается из неё и не заменяет данные клуба демонстрационными клиентами. Затем войдите с учётной записью из общей базы. На существующей базе при обновлении сохраняются локальные данные и подключение Диска.

## Резервные копии на Яндекс Диске

Войдите администратором и откройте **Журналы и настройки → Настройки → Яндекс Диск**. Введите OAuth-токен с правами чтения и записи файлов и нажмите **Сохранить и проверить подключение**. Инструкции Яндекса: [API Диска](https://yandex.ru/dev/disk/rest/), [получение токена вручную](https://yandex.ru/dev/id/doc/ru/tokens/debug-token). Пароль от аккаунта Яндекса вводить в приложение не нужно.

При закрытии приложения крестиком оно предлагает сохранить копию, если добавлялись, редактировались, продлевались, замораживались, удалялись или восстанавливались клиенты. Изменения чёрного списка также учитываются. Обычные посещения и считывания QR-кодов не вызывают предложение. Если отказаться или загрузка завершится ошибкой, необходимость копии сохраняется до следующего выхода. Можно отменить выход или запустить копирование вручную из настроек.

Копии сохраняются в **Легенда / Резервные копии** на Диске. Имя содержит местные дату и время, например `Legenda-backup-20260924-153052-123.db`. После подтверждённой загрузки остаются 10 последних копий; самые старые копии приложения удаляются окончательно. Посторонние файлы в папке не удаляются. Ошибка загрузки не удаляет прежние копии.

Копия содержит всю SQLite-базу: клиентов, посещения, учётные записи и настройки. Токен хранится зашифрованным средствами Windows и не записывается в журнал. После переноса на другой компьютер или к другому пользователю Windows подключите Диск заново. Для восстановления скачайте нужный файл `.db` с Диска и выберите **Восстановить из копии** в настройках приложения.

## Разработка

Откройте `Legenda.sln` в IDE или запустите `./run.ps1`. Скрипт использует локальный SDK из `.tools/dotnet`, если он установлен, иначе системный `dotnet`.

```powershell
dotnet build Legenda.sln -c Release
dotnet test tests/Legenda.App.Tests -c Release
dotnet publish src/Legenda.App/Legenda.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o dist/Legenda-v2-win-x64
```
